# 路由目标函数改帕累托 + In-house lane 升格 + 用户侧路由 profile

Status: ready-for-agent

## Problem Statement

架构师的车道路由函数缺了一整类输入。现行 doctrine 的判定规则只有一条"判断力依赖度"，目标函数写死为"最便宜的胜任车道"，而用户侧真实存在、且 agent 无法探测的约束——额度余量（grok 额度快用完/已用完）、交付时限（赶工时宁快勿精）、模型专长偏好（前端偏 Claude、后端偏 Codex）、临时偏好——完全不在路由函数里。结果是架构师始终按默认路由执行：额度耗尽了还在往 grok 派、赶工时还在等 codex、前端任务错过更擅长的车道，浪费时间且路由质量系统性低于用户自己拍板。

同时，Fallback lane 的语义已过期。它被钉死为"两条 CLI lane 均不可用时的兜底"，其成立前提是 Sonnet 时代的三元约束（能力不敌 gpt、价格不敌 grok、与主会话共享额度）。该 lane 现已挂 Opus，前两条前提落地；用户实际存在主动路由给它的真实动机（前端专长、上下文隔离），维持"仅兜底"禁令只会被实践绕过。

## Solution

架构师保留路由决策权（不做逐任务点菜），路由函数新增用户声明的 profile 作为输入：

1. **输入分两层**：持久判断（专长表、车道排名，每条带成立前提与失效条件）写入用户级规则文件，跨会话生效；易变状态（额度余量、赶工）开工时口头声明，不落盘，声明即进当次路由函数。
2. **目标函数改两段式**：先按判断力依赖度筛出胜任车道集合（不变），再在集合内按帕累托选择（速度/价格/能力/专长，输入=已声明 profile）；无任何声明时退化为最便宜胜任车道——默认行为与现行为完全一致。
3. **Fallback lane 升格并更名为 In-house lane（仓内车道）**：可按专长命中、上下文隔离、额度/时限声明主动路由；带三条固定披露与日期戳前提。
4. **低置信度逃生门**：仅在两种触发条件下弹选项问用户（≥2 个带理由的选项），其余情况直接路由、事后报告。

仓库侧只定义机制（路由接受用户声明的 profile 作为输入、逃生门触发条件、In-house lane 语义）；用户的具体排名与专长表属用户层 profile，不写进仓库 doctrine。

## User Stories

1. 作为用户，我想在开工时口头声明"grok 额度快用完了"，让本次会话的路由自动避开 grok，省得每个任务都眼看着它派错再纠正。
2. 作为用户，我想声明"这次赶时间"，让架构师在胜任集合内偏向最快的车道，而不是默认等最慢的 codex。
3. 作为用户，我想把"前端偏 Claude、后端偏 Codex"这类专长判断写成持久规则，让所有会话的路由都吃到这个输入，不必每次重复说。
4. 作为用户，我想让每条持久判断带上成立前提和失效条件（锚定模型代际），以便模型换代后过期判断不再压着路由。
5. 作为用户，我想在没有做任何声明时得到与现在完全一致的默认路由行为，以便声明机制是纯增量、不惊扰既有工作流。
6. 作为用户，我想在声明的约束互相冲突时（如"赶时间"撞上"正确性关键"）被弹一次带理由的选择题，因为这是真正属于我的取舍。
7. 作为用户，我想在高风险任务且 profile 对决定性维度沉默时被问一次，以免架构师在数据迁移这类难逆转任务上瞎猜。
8. 作为用户，我不想在机械任务、单纯无声明、或车道不可用改道这三种情况下被打断，以便自治编排仍然自治。
9. 作为用户，我想在一批任务并行扇出时最多被问一次、覆盖整批路由计划，而不是每个任务弹一次。
10. 作为架构师会话，我想把"专长表命中"作为同档胜任车道间的 tie-breaker，而不是推翻判断力依赖度主规则，以便正确性判定不被偏好污染。
11. 作为架构师会话，我想主动把前端任务路由给 In-house lane（当声明或专长表指向它时），而不是被"仅兜底"禁令拦住。
12. 作为架构师会话，我想把"有一定复杂度但整体较小"的任务派给 In-house lane 做上下文隔离，而不是自己行内写码破坏"不亲写实现"红线。
13. 作为架构师会话，我想在路由到 In-house lane 时固定披露"同族无跨厂评审、共享主会话额度、单价最贵"，以便用户每次知道代价。
14. 作为架构师会话，我想在改道（车道不可用）时沿用现有规则——改道并显式披露、不弹选项，以便逃生门不与既有改道机制重叠。
15. 作为未来读者，我想看到 lane 词条按角色命名（Routine / Cross-vendor / In-house）而非型号命名，以便换模型不产生名实错位。
16. 作为未来读者，我想在 ADR 里读到"兜底车道为何能被主动路由"的决策记录，以便不误判这是随手改动。
17. 作为上游同步者，我想让这次分叉记录在 ADR 里（按 ADR 0001 的纪律），以便同步上游时知道哪些差异是有意为之。
18. 作为实现 lane（收到本 spec 的执行者），我想拿到明确的文档不变量清单作为验收标准，以便纯散文变更也有可判定的完成定义。

## Implementation Decisions

- **改动落点（全部为文档，零代码）**：
  - 编排 skill doctrine（`skills/orchestration/SKILL.md`）：车道表 Fallback→In-house 及其 route-when；判定规则改两段式（胜任集合筛选 + 集合内帕累托）；新增"用户侧路由 profile"输入说明与"低置信度逃生门"小节；Cost discipline 一节拆分——架构师上下文经济学三条原封不动，仅替换"最便宜胜任车道"这一句的地位。
  - 词汇表（`CONTEXT.md`）：Fallback lane 词条改为 In-house lane，释义与 _Avoid_ 重写；与 SKILL.md 车道表命名一一对应。
  - `agents/implementer.md`：description 与正文去掉"仅当两条 CLI lane 不可用"的兜底限定，改为可主动路由的 In-house lane 语义，保留五部 spec 契约与报告格式不动。
  - ADR **0006**（0005 已被上一轮占用）：《路由目标函数从成本最小改为胜任集合内帕累托选择；In-house lane 升格》。
  - 用户级规则文件（`~/.claude/rules/fable-advisor.md`，**仓外交付物**，不进 git）：lane routing 段落扩为 profile——专长表、三车道排名（均带失效条件与日期戳）、易变状态口头声明机制说明；grok 未认证期间 codex 为主的既有覆盖保留。
- **In-house lane 三条固定披露**：同族无跨厂评审；与主会话共享 Anthropic 额度；按用户当前排名单价最贵。
- **日期戳前提**：In-house lane 当前挂 Opus（2026-07，因 Sonnet 定位尴尬——价格涨幅超过能力）；换回新 Sonnet 时重估其路由权重。
- **逃生门触发条件（穷举）**：① 已声明约束在决定性维度冲突；② 高风险任务（正确性关键/难逆转）且 profile 对决定性维度沉默。反例（明确不触发）：机械任务、单纯无声明、车道不可用改道。扇出整批最多弹一次。
- **红线不动**：架构师"不亲写实现代码"维持原样，行内只留琐碎级（一两行）；spawn 护栏、receipt gate 两个门禁机制零改动。
- **层次分离**：仓库 doctrine 只承载机制与中立措辞（保留"grok vs codex 是故障分布问题"的中立立场）；用户的能力排名、专长表是用户层经验判断，只进用户规则文件。

## Testing Decisions

- 无可执行校验器（纯散文/词汇变更，仓内唯一测试装置 pytest 只覆盖 hook，不适用）——按约定以**一次性结构化检查**验收，不新建常驻测试装置。
- 文档不变量（验收标准，逐条可判定）：
  1. 全仓 grep "Fallback lane" → 除历史 ADR（0001–0005）外零命中；
  2. SKILL.md 含两段式判定规则，且含显式不变量句"无任何声明时退化为最便宜胜任车道"；
  3. CONTEXT.md 三车道词条命名与 SKILL.md 车道表一一对应，In-house lane 词条含三条固定披露与日期戳前提；
  4. `agents/implementer.md` description 不再含"仅当两条 CLI lane 不可用"限定；
  5. diff 限于上述落点，hooks/、scripts/、tests/ 零改动。
- 好测试的定义在此语境下 = 不变量在文档改错时必然失败（例如漏改 agents 描述会被第 4 条抓住），而非仅确认文件存在。

## Out of Scope

- 逐任务交互式路由（点菜模式）——已在拷问中被否决（Q1 选 A）。
- 易变状态落盘（routing-profile 文件、额度跟踪文件）——口头声明即可，落盘必然过期。
- 文档一致性常驻测试装置（docs-lint pytest）——投机性抽象。
- 任何代码、hook、runner、脚本改动；spawn 护栏与 receipt gate 语义。
- 额度探测自动化（让 agent 自己查各 CLI 余量）——当前无可靠探测面，仍属用户独有事实。
- 上游同步本身——本次只按 ADR 0001 纪律记录分叉。
