## 3. 问题一：逐票验证

**结论。** 椰椰说「改歪了」，这一判断部分成立：

- 成立的部分：ADR 0029 把椰椰 10-01 的「能一起验的就集中一起验」落成了「比单张契约更宽的昂贵检查归批次」，并退役了「共用昂贵准备」。按现行条文，只覆盖一张票的昂贵检查仍归那张票，即使几张票的同类检查可以一起做（第 3.2 节第 3 条）。选项 1B 修补这一处。
- 更大的成因在执行：调用表格的 01 与 02、图表的 03 与 04，按现行条文本该并成一份契约、验收一次。这条规则写在 `SKILL.md` 里，主会话也加载了，但没有执行（第 3.2 节第 1 条）。

「拆成 8 个会话各自完成岂不是更快？」按这次的跑法，前端部分没有从编排中得到好处：5 张前端票在一条线上逐张派发、验收、提交，每张一整轮往返（已核实）。编排应当带来三项收益：同区域的票并成一份契约、验收一次；没有共同源文件的两组并行；昂贵检查整批只跑一次。前两项这次都没有拿到，第二项还受任务件 C5「前端票在主工作区串行」限制；第三项里，全量测试从一开始就按批次跑，渲染截图到椰椰 18:58 打断之后才改为整批（已核实）。后端 06 至 08 在两个隔离工作树里与前端同时进行，这一部分编排起了作用（已核实）。

椰椰 10-04 补充：并票、少跑几次测试只是表面，根本在于主会话缺少全局意识。补救见 [实施方案](spec.md) D1。

### 3.2 成因

1. **主因：已有规则没有执行。** 合票、按契约验收、提交按授权和回滚边界拆，这三条在 `SKILL.md` 和记忆索引里都写着。主会话仍把逐票提交作为推荐项提给椰椰，理由是「与上一轮的做法相同」，并逐票派发（已核实）。D2 经椰椰批准，所以逐票验收后提交是有授权的；问题在于推荐它的是主会话，主会话也没有给出按契约提交的选项，没有说明它与合票规则冲突（已核实）。主会话为什么没有执行这些规则，记录里没有直接证据；从推荐语看，它沿用了上一轮的习惯，并且以票据表为规划单位（推断）。
2. **缺少派发前的整体验证规划。** 条文里，检查是写每份契约时随契约附上的。没有一条规则要求架构师在派发之前，对整个任务写下：哪些检查覆盖哪些票，由谁执行，在哪个检查点执行（已核实，`SKILL.md` 全文）。cc-usage 的任务件里，规划单位是票据表；验证设计也按票写（C4、D2，已核实）。
3. **ADR 0029 把椰椰的声明落窄了。** 椰椰 10-01 说的是「能一起验的就集中一起验」。ADR 0029 落成的条文只把「比单张契约更宽的昂贵检查」归到批次，并在决策 2 退役了 ADR 0020 决策 3 的触发词：「共用昂贵准备的合同在最后一张落地后一起验一次」（已核实，条文对照）。按现行条文，只覆盖一张票的昂贵检查仍归那张票，即使几张票的同类检查可以一起做。渲染截图共用隔离服务和浏览器，范围却只覆盖一张票，按现行条文不归批次（推断）。cc-usage 的记忆正文写了「渲染截图也合并为一轮」，但会话开始时它不在索引行里，规划时没有到达主会话（已核实，第 2 节的读取时刻）。
4. **例外条款容易读宽。** 例外之一是「一张票需要另一张票已验证的结果」。票表写着「02 依赖 01」，但这个依赖是先后顺序（02 在 01 改过的文件上继续改），不是需要 01 先验收（已核实：票表与文件清单；主会话按例外处理是推断）。主会话还把「交给同一个 worker」做成了用 `SendMessage` 逐张续派，每张仍是单独的契约（已核实）。条文写的是「go to one worker as one contract」，一个 worker 不等于一份契约。
5. **把提交边界和验收边界绑在一起。** 逐票提交并不要求逐票验收：可以逐票提交车道自己检查过的改动，一组只验收一次，验收发现的缺陷用返工提交修正。D6 在 18:58 之后做的正是这样（已核实）。本次逐票验收来自 D2 的措辞「每票验收后提交」，不是 Git 的限制（已核实）。
6. **插件之外的因素**（都需要椰椰授权才能改）：
   - 记忆 `render-verification-via-headless-chrome.md`：「UI 票据完成后由架构侧亲自跑」；`ui-tickets-need-render-verification.md`：「任何 UI 票据的验收必须包含「启动应用 → 截图」」。主会话 16:32 读过前者（已核实）；它们是 C4 的来源，这一点是推断。
   - 记忆 `cc-usage-app-ts-is-the-parallelism-chokepoint.md` 的最后一条：「先后派发的两份契约,前一份验收并提交后再派下一份」。它保护的是车道从干净工作树起步（已核实）。
   - 会话开始时，记忆 `test-run-budget.md` 的索引行没有提渲染。18:59 该会话把索引行改为提到渲染截图，又往正文追加了一条，写成「主会话每张前端票都重启隔离服务、单独截图验收」，实际只有票 01 做过（已核实）。
