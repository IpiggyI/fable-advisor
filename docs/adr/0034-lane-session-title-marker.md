# 0034 — 车道会话名前加 `[车道]` 标识

- **Status**: accepted（2026-10-18 椰椰的要求；未发布，待下一版本）
- **Date**: 2026-10-18
- **影响范围**:
  - `plugin/scripts/run-grok.mjs`、`plugin/scripts/run-codex.mjs`：prompt 第一行。
  - `plugin/skills/orchestration/runners.md` 的 `title` 条目与 `docs/zh/` 孪生：标识说明，以及标题边界的写法。
  - `tests/test_runner_contract.py`：所有断言 prompt 第一行的用例。
- **关联**: 修订 [ADR 0018](./0018-post-5-1-tuning.md) 决策 2（第一行是标题原文）；6.4.1 的标题写法规则不变。

## 背景

6.4.1 把 `title` 规定为不超过 12 个汉字的目标短语。椰椰 2026-10-18 使用后反馈：codex / grok 的会话列表里，车道会话和用户自己开的普通会话看起来一样，无法区分。

## 决策

1. **runner 加标识，不靠主代理写。** 两个 runner 把 prompt 第一行写成 `[车道] ` 加 `title`；省略 `title` 时用 slug 代替。标识是固定文本，由代码保证每次都有。
2. **标识文字取 `[车道]`。** 椰椰在候选中选定；与 `CONTEXT.md` 的术语「车道」一致。
3. **长度上限只计标题。** 12 个汉字或 6 个英文词不含标识。
4. **标题边界写成可检查的条件。** 6.4.1 的 `title` 条目逐项点名禁写项（票据编号、基名、层标签、子项清单、冒号后接细节）。这五项都在 6.4.1 之前的 codex 车道会话标题里出现过（本机 `~/.codex/sessions`，例如「1008 票 01:补查询统计,未变文件不再重读重写」「令牌续期契约 B:…(票据 02、03 后端)」），所以边界保留。椰椰判定逐项点名属于粉色大象问题，即点名禁写项可能把注意力引向它们；这一效果未验证。条目改为一个条件：标题是只由描述目标的词组成的名词短语，不含数字编号和标点，其余信息进五个部分。这个条件覆盖全部五项。
5. **`[fable-advisor]` 仍退役。** 测试继续断言 prompt 不含它。

## 未采纳

- **恢复 `[fable-advisor] <slug>`。** 比 `[车道]` 长，挤占会话列表的显示宽度。
- **在 doctrine 里要求主代理把标识写进 `title`。** 模型可能漏写或写错；固定文本属于代码。
- **标识带角色（`[车道·worker]`）。** 会话名更长；角色信息已在 prompt 正文里。

## 待核验

会话列表的实际显示（含截断）未观测；椰椰下次真实派发车道后确认。

决策 4 的条件能否让主代理写出合格标题，未经对照验证。对照任务：给一个带工单编号、分前后端的任务，主代理按新条目写 `title`；标题不含编号和标点、不超过 12 个汉字即通过。
