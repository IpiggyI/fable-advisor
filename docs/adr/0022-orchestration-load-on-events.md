# 0022 — 编排技能按事件加载：技能描述收窄，全局入口改为事件触发

- **Status**: accepted（2026-09-28 椰椰确认定稿；定稿文本经 `gpt-6-astra` xhigh advisor 两轮裁决；决策 5 的上限已被 [ADR 0029](./0029-scoped-contract-checks-and-batch-defaults.md) 决策 8 上调到 2340）
- **Date**: 2026-09-28
- **影响范围**: `plugin/skills/orchestration/SKILL.md` 第 3 行 `description`、`docs/zh/skills/orchestration/SKILL.md` 第 3 行；`.scratch/tiers-and-routing-6-0/spec.md` TR-9 与 S4 的词数上限。技能正文不变。用户全局入口（prompts 仓库 `current-prompts/CLAUDE.en.md`、`CLAUDE.zh.md` 的平台适配段）同期改写，归用户维护，不在本仓。
- **关联**: 修订 [ADR 0015](./0015-global-orchestration-entry.md) 决策 10 的描述文本；全局入口的来历见 ADR 0015 背景。任务记录 `.scratch/orchestration-lazy-load/proposal.md`。codex-advisor 同类改动记在该仓 ADR 0007。

## 背景

技能正文本来按需加载，常驻上下文的只有描述。但两层文字把加载提前到了几乎每个任务：

1. 全局入口按任务类型触发："交付物改动、超出有界事实查询的调查、重要决策、交付验收"前先读并遵循。几乎每个编码任务都命中第一类。同段 "Model allocation: first read …" 容易被读成会话开始就读路由档案。
2. 描述写 "Use when deciding how to carry out a deliverable change"，同样覆盖每次改动。描述末尾的 "consulting the advisor" 还可能与宿主自带的 `advisor` 工具混淆（推断，未验证）。

2026-09-19 至 2026-09-28 的 Claude Code 会话记录：12 个会话加载了本技能，9 个在第一条人类消息后就加载，其中 6 个加载后没有任何派发（画图、合并分支、问答、体检、一次分析）；13 个会话读了路由档案，9 个在第一条消息就读，5 个整个会话没有派发。

## 决策

1. **触发条件从任务类型改为事件。** 本技能在四类事件时加载：用户或上游指令要求编排或委派，或没有姿态指令时即将编辑受任务件约束的交付物；即将开始范围很宽、可独立并行、或只需结论进入主线程的读取；即将派发或验收任一子代理或车道；到达决策类型门的五个节点之一。其余任务不加载。
2. **描述即触发清单。** 新描述列出上述四类事件，决策门五项写全。描述因此从约 35 词增到约 85 词，超过 ADR 0015 决策 10 的目标；插件用户未必有全局入口，描述是他们唯一的触发来源，所以取完整。
3. **决策门清单有两处。** 技能正文 `## Decision-type gate` 是唯一的规则源；描述与全局入口只抄触发条件。门清单改动时，描述与全局入口同步改。
4. **路由档案只在分配模型时读。** 全局入口改为"为派发分配模型时读取，其他时候不读"。
5. **`SKILL.md` 词数上限从 2160 上调到 2210。** 2026-09-28 椰椰选定。新描述使全文 `wc -w` 从 2160 增到 2206，超出的 46 词全部来自 frontmatter 描述；正文（不含 frontmatter）2115 词。ADR 0021 的复盘条件"逼近上限时先按 ADR 0012 判断沉降，不继续上调"仍适用于正文。

## 未采纳

- 删除全局入口，只靠描述触发：回到"忘记加载"的状态。
- 全局入口只保留"派发时加载"：姿态判定、派 `explorer` 的判据与决策门都写在正文里，未派发时会漏读。
- 保留"超出有界事实查询的调查"作为触发：它覆盖几乎所有调查；改为技能 `SKILL.md` 成本段派 `explorer` 的三个判据。

## 复盘条件

- 部署后在真实会话重跑会话记录扫描：无委派任务仍加载本技能或读路由档案 ≥2 次，重议描述措辞。
- 任一需要本技能的会话漏加载（编排姿态下主代理自改交付物，或到达决策门未咨询 advisor）≥1 次，重议触发清单。
- 决策门清单变动：同步描述与全局入口。
