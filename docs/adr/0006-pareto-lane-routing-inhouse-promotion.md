# 0006 — 路由目标函数从成本最小改为胜任集合内帕累托选择；In-house lane 升格

- **Status**: accepted
- **Date**: 2026-07-26
- **影响范围**: `skills/orchestration/SKILL.md`、根目录 `CONTEXT.md`、`agents/implementer.md`、`README.md`、`.claude-plugin/plugin.json`；用户侧 profile 在私有规则 `~/.claude/rules/fable-advisor.md`（仓外）
- **关联**: [ADR 0005](./0005-model-routing-and-receipt-gate.md)（`Fallback` lane 默认改 opus 及其上下文隔离论证）；[ADR 0001](./0001-upstream-sync-fork.md)（分叉纪律）；spec 归档 `.scratch/pareto-lane-routing/spec.md`

## 背景

现行路由函数只有一条判定规则（判断力依赖度）与一个写死的目标（最便宜的胜任车道）。真实约束里有一整类输入不在函数中，且**架构师无法探测**：CLI 额度余量、交付时限压力、用户经验里的模型专长（前端偏 Claude、后端偏 Codex）。结果是默认路由与用户当次意图系统性错位——额度耗尽仍往 grok 派、赶工仍等最慢的 codex、专长任务错过更合适的车道。这类事实属用户独有，只能作为**声明**进入路由，不能靠自动探测补齐。

同时 `Fallback` lane 的禁令前提已落地。它被钉死为"仅两条 CLI lane 均不可用时的兜底"，成立前提是 Sonnet 时代的三元约束：能力不敌 gpt、价格不敌 grok、与主会话共享额度。[ADR 0005](./0005-model-routing-and-receipt-gate.md) 将该 lane 改挂 opus 后，前两条前提已不再成立；第三条仍成立，但那是**代价**而非**禁令**。用户已存在主动路由给它的真实动机（专长命中、上下文隔离），维持"仅兜底"只会被实践绕过。

## 选项对比

### 决策一：如何把用户侧约束接入路由

| 方案 | 优点 | 缺点 | 风险 |
|------|------|------|------|
| 维持现状（纯成本最小） | 规则最简、无新概念 | 用户独有事实永远进不了函数；每个任务都要事后纠正 | 路由质量系统性低于用户自己拍板 |
| 逐任务交互式点菜 | 每次都对 | 把信息缺失当成决策权问题修；自治编排退化为人工调度 | 编排价值归零，每任务一次打断 |
| **两段式：胜任集合筛选 + 集合内帕累托（选定）** | 正确性判定不被偏好污染；声明是纯增量输入 | 失去单目标规则的简洁性，判定分两步 | 帕累托维度被误用来推翻胜任筛选（已在 doctrine 中明文禁止） |
| 直接把偏好并入单一评分函数 | 一步出结果 | 偏好与正确性同权可加，赶工权重可压倒正确性关键判定 | 高风险任务被速度偏好带走 |

### 决策二：用户 profile 落在哪一层

| 方案 | 优点 | 缺点 | 风险 |
|------|------|------|------|
| 具体排名与专长表写进仓库 doctrine | 随 fork 传播、即装即用 | 那是一名用户的经验判断，不是项目准则；与"grok vs codex 不是能力排名"的中立立场冲突 | 他人 fork 继承不属于自己的偏见 |
| **机制入库、判断入用户规则（选定）** | 仓库只定义"路由接受声明作为输入"；具体排名、专长表留在私有规则，逐条带前提与失效条件 | 装两处 | 用户规则未装时退化为默认行为（可接受，见不变量） |
| 易变状态落盘（routing-profile / 额度跟踪文件） | 跨会话可读 | 额度与工期写下即过期 | 陈旧数据静默压着路由，比没有更糟 |

### 决策三：什么时候该问用户

| 方案 | 优点 | 缺点 | 风险 |
|------|------|------|------|
| 不确定就问 | 不会瞎猜 | "不确定"无边界，机械任务也会被问 | 打断成灾，编排自治瓦解 |
| 从不问、一律自行裁决 | 零打断 | 用户独有的取舍被架构师代做 | 赶工撞正确性关键时替用户选错 |
| **两触发器 + 三反例（选定）** | 触发条件穷举可判定；扇出整批最多一次 | 需要维护一份显式清单 | 边界个案落在清单外时按不触发处理（默认自治，事后披露） |

## 决策

**选择**:

1. **目标函数改两段式**：先按判断力依赖度筛出胜任车道集合（原规则不变），再在集合内按帕累托维度（速度/价格/能力/专长）择一，输入是用户已声明的 profile。专长命中只是**同档胜任车道间的 tie-breaker**，不得推翻第一段的筛选结果。显式不变量入库："With no declarations, this degrades to the cheapest adequate lane — the pre-profile default behavior, unchanged."
2. **profile 分两层**：持久判断（专长表、车道排名）写用户级规则文件，逐条带成立前提、失效条件与日期戳，锚定模型代际；易变状态（额度余量、赶工）开工时口头声明，仅当次会话有效、不落盘。仓库只定义机制。
3. **`Fallback` lane 升格并更名 In-house lane**：可按专长命中、上下文隔离、额度/时限声明主动路由，同时保留可用性兜底职责；每次路由固定披露三条代价（同族无跨厂评审、共享主会话额度、按用户当前排名单价最贵）；日期戳前提——当前挂 Opus（2026-07，因 Sonnet 价格涨幅超过能力），换回未来 Sonnet 时重估其路由权重。
4. **低置信度逃生门**：仅两个触发器——① 已声明约束在决定性维度冲突；② 高风险任务（正确性关键/难逆转）且 profile 对决定性维度沉默。触发时给 ≥2 个带理由的选项。明确不触发：spec 完全决定的机械任务、单纯没有声明、车道不可用改道（沿用既有"改道 + 显式披露"规则）。并行扇出整批最多问一次，覆盖整批路由计划。

**核心理由**:

1. **信息缺失用信息修，不用决策权转移修**。路由质量差的原因是函数缺输入，不是架构师不该决策；补输入保住自治，点菜模式则把编排价值一并交出。
2. **正确性筛选先于偏好**。两段式的顺序本身就是防线：帕累托只在胜任集合内比较，赶工或专长偏好无法把一个能力不够的车道抬进正确性关键任务。单一加权评分做不到这一点。
3. **禁令的前提落地则禁令随之落地**（全局规则"假设会过期"）。In-house lane 的"仅兜底"是 Sonnet 时代三元约束的结论；[ADR 0005](./0005-model-routing-and-receipt-gate.md) 换代后两条前提消失，剩下的第三条（共享主会话额度）性质是代价，应转为**逐次披露**而不是继续当禁令。
4. **层次分离**：能力排名是用户经验，仓库 doctrine 保持中立（"Grok vs codex 不是能力排名，是故障分布问题"原文保留）。公开 fork 不承载他人的私有偏好。
5. **落盘必过期**：额度与工期是会话级事实，口头声明 + 当次生效是唯一不会静默陈旧的形态。

## 实施代价

- `skills/orchestration/SKILL.md`：总则句改两段式；车道表 Fallback 行改 In-house 行（含日期戳前提与三披露）；Deciding rule 拆两段并写入不变量句；新增"User routing profile"一节（两层输入 + 逃生门）；Cost discipline 三条规则原封不动，仅在"什么留给架构师"段落补一句——帕累托只在车道之间选择，不用来换掉派活本身。
- 根目录 `CONTEXT.md`：**`Fallback` lane** 词条改写为 **In-house lane（仓内车道）**；**lane** 词条枚举同步为 Routine / Cross-vendor / In-house。
- `agents/implementer.md`：frontmatter description 与正文首段去掉"仅当两条 CLI lane 不可用"限定，改为主动路由动机 + 可用性兜底并存；trade-off 段改为"每次路由都应带三披露"；`model: opus`、五部 spec 契约、报告格式、Rules 全部不动。
- `README.md`：车道表 `Fallback` 行改 In-house 行；in-house lane bullet 去 fallback-only 措辞（"prefer a CLI lane whenever one is available" → "routine work still defaults to the CLI lanes; routing here is deliberate and disclosed"）；开篇标语改两段式；"Upgrading" 段落只追加 v3.4 条目、历史叙述不改写。`.claude-plugin/plugin.json`：version 3.3.0 → 3.4.0（路由语义变更打 minor，沿用 [ADR 0005](./0005-model-routing-and-receipt-gate.md) 先例），description 中的 fallback-only 措辞同步改写。
- 用户私有规则 `~/.claude/rules/fable-advisor.md`（仓外）：lane routing 条目区后新增 routing profile 区（专长表、三车道排名、易变状态声明机制、逃生门引用），逐条带日期与失效条件。
- 历史 ADR（0001–0005）中的 "Fallback" 字样不追改——历史文档记录当时的决策。
- 无可执行校验器（纯散文变更）；以一次性结构化 grep 检查验收，不新建常驻测试装置。

## 复盘条件

- 任一模型换代（Grok 4.5 / GPT-5.6 / Opus 5）→ 用户规则中对应的排名与专长条目按其失效条件重估。
- In-house lane 换回未来 Sonnet → 重估其在帕累托维度上的权重与三披露中的"单价最贵"一条。
- 逃生门实际触发频率异常（几乎不触发 = 触发器过窄；频繁打断 = 过宽）→ 重新界定两个触发器。
- 出现可靠的额度探测面（CLI 暴露余量查询）→ 额度可从"用户声明"改为可探测输入，重估易变状态层。
- grok CLI 认证恢复 → 用户规则中"codex 为主车道"的覆盖失效，回归 skill 默认路由（该条已在用户规则中自带失效条件）。
