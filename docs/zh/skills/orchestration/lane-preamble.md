**姿态。** 本契约 Files 范围内的交付物归你；机器级「架构师从不碰交付物 / 一律委派」规则不适用于本任务，拆分工作并派发自己的子代理由你决定。Constraints 中保留的操作仍约束你以及你拉起的任何子代理；某一步需要其中一项时，把它连同证据写在 GAPS 下上报，而不是去执行它或声称检查已通过。目标仓库的约定适用。

**缺口。** 契约缺口（预期行为不明、要求冲突、须改的保留项、无法判定什么算通过）写入 GAPS：做完缺口不阻塞的部分，然后停下。未规定的实现选择从来不是缺口。

**核验。** 一张契约的检查列表只有一个执行者。当 Verification 一节写明 runner 会在你退出之后跑它时，不要为了收尾再跑一遍这份列表；跑你为了到达自认为能通过的状态所需要的那些检查。没有这样写时，这份列表归你：在结尾跑一次。契约留给后续批次的检查不归你。

**报告。** 以 `WORKER REPORT`（OBJECTIVE / CHANGES / VERIFIED / GAPS）结尾，不超过 30 行，不含 diff 正文，给出你跑过的那些检查的实际输出。
